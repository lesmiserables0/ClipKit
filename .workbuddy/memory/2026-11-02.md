## 追加：修复三个 bug（搜索聚焦 / 导航栏变宽 / 搜索位置）

1. **搜索框点击不聚焦**：根因是面板 `.nonactivatingPanel`，点击不会成为 key window，TextField 拿不到焦点。新增 `ClipKitPanel`（重写 `canBecomeKey`/`canBecomeMain` 为 true），`createPanel` 改用它并设置 `becomesKeyOnlyIfNeeded = false`，使点击面板即可成为 key、输入框可聚焦；输入框挂载时 `.onAppear { searchFocused = true }` 立即聚焦。
2. **点实用链接导航栏变宽**：原来 HStack 用两端 Spacer 居中、无宽度约束，选中/元素变化会把行撑开。改为把「剪贴板 + 用户分类 + 加号」放进横向 `ScrollView(.horizontal)` + `.frame(maxWidth:.infinity)`，齿轮与关闭按钮固定右侧，选中分类不再撑宽（溢出则滚动）。
3. **导航栏放在剪贴板左边**：搜索按钮/输入框移到「剪贴板」左侧。

验证：swiftc -typecheck 0 error / 0 warning。

## 再修：点实用链接导航栏依旧变宽（根因在 AppKit 层）

上次「ScrollView + maxWidth」写法没真正生效——因为 `ClipKitApp.createPanel` 把 `NSHostingView` 直接当 `contentView`，而 `NSHostingView` 的 `intrinsicContentSize` 取决于 SwiftUI 内容的理想宽度。contentView 未被约束钉死，点击分类触发重新布局使内容理想宽度变化时，AppKit 会让窗口去"贴合"内容尺寸，从而把面板（及铺满面板的导航栏）反向撑宽。

根因修复：`createPanel` 改为用容器 `NSView` 包住 `NSHostingView`，并对 hostingView 四边加 Auto Layout 约束钉到面板内容区（`translatesAutoresizingMaskIntoConstraints = false`）。这样 SwiftUI 始终拿到固定有限宽度，`maxWidth:.infinity` 才真正生效，窗口尺寸不再被内容反向影响。

验证：swiftc -typecheck 0 error / 0 warning。
